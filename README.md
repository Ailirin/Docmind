# DocMind

Учебный / портфолио-проект: сервис, который принимает медицинские PDF (выписки, рецепты, диагнозы), разбирает их и отдаёт структурированный результат.

Ниже — задача, решение и результат простыми словами, затем короткое локальное демо.  
Где какой файл лежит: [`FILES.md`](FILES.md).

---

## Задача

В клиниках и страховых компаниях много сканов и PDF: выписки, рецепты, заключения.  
Людям приходится **вручную** читать файлы и переносить в систему ФИО, диагноз, препараты, даты.

Это медленно, дорого и легко ошибиться. При росте объёма документов ручная обработка не масштабируется.

Нужен сервис, который:

1. принимает документ;
2. сам извлекает из него важные поля;
3. показывает статус и результат;
4. не «висит» у пользователя, пока идёт тяжёлая обработка.

---

## Решение

**DocMind** — конвейер обработки документов:

| Шаг | Что происходит простыми словами |
|-----|----------------------------------|
| 1. Приём | Клиент загружает PDF. Система сразу отвечает: «принято, вот номер заявки». |
| 2. Очередь | Тяжёлая работа уходит в отдельный фоновый процесс — сайт/API не тормозит. |
| 3. Разбор | Из PDF достаётся текст, определяется тип документа (выписка / рецепт / диагноз). |
| 4. Сущности | Из текста собираются поля: пациент, диагноз (код МКБ), лечение, дата. |
| 5. Результат | Данные сохраняются; по номеру заявки можно узнать статус и готовый результат. |
| 6. Контроль | Есть простая веб-админка со списком документов (с постраничным просмотром). |
| 7. Наблюдение | Видно, сколько документов обработано, где ошибки, что пишут логи. |

Дополнительно для безопасной демонстрации и будущего деплоя:

- доступ к API по секретному ключу;
- проверка, что файл действительно PDF и не слишком большой;
- в публичном ответе API не светится путь к файлу на диске;
- метрики закрыты паролем; служебный порт фонового процесса снаружи не открыт.

Разбор полей можно делать двумя режимами:

- **учебный (стабильный)** — по правилам, без нейросети (удобно для тестов и демо);
- **с языковой моделью** — когда нужна более «умная» вытяжка из свободного текста.

## Результат

Что получает команда / заказчик после внедрения такого подхода:

| Было | Стало |
|------|--------|
| Человек читает PDF и копирует поля | Система заполняет карточку документа сама |
| Долгое ожидание ответа при разборе | Сразу «принято»; результат догоняет по статусу |
| Непонятно, где застрял документ | Статусы: в очереди → в работе → готово / ошибка |
| Сложно показать работу сервиса | Админка + дашборды мониторинга |
| Страшно отдавать наружу учебный API | Ключ доступа, лимиты на файл, закрытые метрики |

На выходе по каждому документу — не «просто текст», а **структурированные данные**, например:

- кто пациент;
- какой диагноз (код и название);
- какое лечение (препарат и дозировка);
- дата документа;
- исходный извлечённый текст (для проверки человеком).

Качество учебного режима измеряется на размеченных примерах (отдельный прогон проверки точности).

## Как это выглядит для пользователя

```text
Загрузка PDF
    → система сразу даёт номер документа
    → в фоне: текст → тип → поля
    → статус «готово» или «ошибка»
    → результат в API или в админке
```

Типичный путь менеджера на демо:

1. Открыть админку и увидеть список документов.
2. Загрузить тестовый PDF.
3. Обновить карточку — увидеть статус и извлечённые поля.
4. При желании открыть Grafana и показать «сервис под контролем».

## Быстрый просмотр демо (для команды)

Нужны Docker Desktop и несколько минут.

```powershell
cd D:\Project\DocMind
Copy-Item .env.example .env
docker compose up -d --build
```

| Что открыть | Адрес | Зачем |
|-------------|--------|--------|
| Описание API | http://127.0.0.1:8000/docs | Загрузить PDF через интерфейс |
| Админка документов | http://127.0.0.1:8000/admin/documents | Список и карточки (постранично) |
| Мониторинг | http://127.0.0.1:3000 | Графики и логи (Grafana) |

Доступы по умолчанию для локальной демо-среды задаются в `.env.example` и `docker-compose.yml` (логин/пароль админки, ключ API, пароль метрик).  
**Реальные секреты** храните только в своём `.env` и не выкладывайте в git.

После правок кода в образе:

```powershell
docker compose up -d --build --force-recreate api
```

(иначе контейнер продолжит работать со старой сборкой.)

Тестовые PDF лежат в папке `samples/`.

## Что уже заложено «как во взрослом сервисе»

Без углубления в технологии — смысл для управления проектом:

- **Очередь задач** — пики загрузок не роняют интерфейс.
- **Отдельный обработчик** — разбор документов масштабируется отдельно от приёма файлов.
- **Журнал ошибок обработки** — «битые» задачи не теряются бесследно.
- **Автопроверки при каждом изменении** — линтер и тесты в CI.
- **Миграции базы** — схема данных версионируется.
- **Единый идентификатор запроса** — проще разбирать инциденты от загрузки до результата.

Подробности по файлам и командам запуска: [`FILES.md`](FILES.md).

## Куда можно развивать дальше

| Направление | Зачем бизнесу |
|-------------|----------------|
| Поиск с опорой на содержимое документов (RAG) | Спрашивать: «какой диагноз у пациента X?» по уже загруженным файлам |
| Распознавание сканов (OCR) | Работать не только с «текстовыми» PDF |
| Облачное хранилище файлов | Готовность к кластеру и бэкапам |
| Полноценные роли и политики доступа | Несколько клиник / отделов |
| Повтор ошибочных задач с умом | Меньше ручного вмешательства при сбоях сети |
